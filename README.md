# 综艺衍生内容管家 VarietyPilot v2.1.2

MoviePilot v3 插件。解决综艺订阅的三件事：

1. **加更、彩蛋、纯享、还有加更、超前营业** 这类衍生内容，不再靠关键词排除（排除就看不到更新），也不占用正片集号（不排除就挤掉正片）。
2. **按 TMDB 特别季的真实集号落位**，让极影视、Emby 都能像正常剧集一样刮削出来、点开能看。
3. **自动跟踪你在 MP 里已经订阅的综艺**，不用再把剧名和 TMDB ID 抄一遍。

---

## 一、它怎么解决问题

### 核心事实

TMDB 的综艺条目本来就有「特别篇」季（Season 0），而且集名是结构化的中文：

| 剧 | 特别篇规模 | 集名样例 |
|---|---|---|
| 现在就出发（TMDB 231620） | 167 集，简介写明「涵盖彩蛋及加更内容」 | `第3季 第1期加更`、`第3季 第1期还有加更`、`第3季 特别加更` |
| 我家那闺女（TMDB 126490） | 122 集 | `2026 加更版第2期：…`、`2026 超前营业第2期：…`、`2026 闺女生活盲盒大放送第1期：…` |

也就是说：**这些衍生内容在 TMDB 里是有正式集号的**，只是站点发布名和 TMDB 集名对不上，播放器认不出来。

所以插件不做「顺延到特别季尾部」这种猜测，而是把发布标题解析成字段，和 TMDB 特别季集名做字段比对，找到真实集号。

### 处理链路

```
定时扫描 → 站点搜索 → 解析标题 → 匹配 TMDB 特别季 → 去重 → 下载
                                                          ↓
        整理渲染前改写季集号 → Season 00/剧名 - S00E128 - 第3季 第1期加更.mkv
                                                          ↓
                                        刷新媒体库 → 极影视 / Emby 显示为特别篇
```

关键点：在整理**渲染前**就把季集号改掉，文件一步到位落到 `Season 00`，不产生「先落正片目录再搬走」的中间状态，也不动已经入库的文件。

文件本身始终由 MP 自己整理：按你设置的整理模式（硬链接/复制/移动）落到媒体库，插件不改文件、不搬目录，只在整理渲染前改写季集号。三层保障：

| 层 | 时机 | 作用 |
|---|---|---|
| 元数据对齐 | 提交下载时 | 把 `meta_info` 的季集改成 S00Exx，下载历史与「已存在」判断不再按正片集号记账 |
| 渲染前改写 | 整理开始时 | 改 `rename_dict` 的 season/episode，模板自然渲染出 `Season 00` 与特别集名 |
| 渲染后兜底 | 渲染完成 | 模板里硬编码的 `S04E08`、`Season 04` 再改一遍 |

如果开了「未接管资源也强制进特别季」，连手动下载、插件没有对应任务的衍生文件也会落到 Season 00 的 9xx 段，不会占用正片集号。

## 二、安装

### 方式一：插件市场在线安装（推荐）

本仓库本身就是一个 MoviePilot 插件库，把地址加进市场列表即可。

1. 在 MoviePilot 的环境变量里追加本仓库地址（`PLUGIN_MARKET` 用英文逗号分隔，原来的官方市场务必保留）：

   ```bash
   PLUGIN_MARKET=https://github.com/jxxghp/MoviePilot-Plugins,https://github.com/Zuomeng00/VarietyPilot
   ```

2. 重启 MoviePilot。

3. 打开「插件」页面 → 市场里搜索 **综艺衍生内容管家** → 安装。

4. 安装完成后启用插件，按下文「三、配置」填剧列表。

> 插件 ID 是 `VarietyPilot`，与官方市场不重名，不会出现来源冲突。
> 若之后仓库改名或迁移，改 `PLUGIN_MARKET` 里的地址即可，插件配置不会丢。

### 方式二：手动放置目录

不想动环境变量时，把 `plugins.v3/varietypilot` 整个目录拷到 MoviePilot 的插件目录，重启即可：

```
/config/plugins/varietypilot/__init__.py
/config/plugins/varietypilot/titles.py
/config/plugins/varietypilot/sxxindex.py
/config/plugins/varietypilot/renaming.py
/config/plugins/varietypilot/pipeline.py
/config/plugins/varietypilot/store.py
```

### 方式三：本地插件仓（开发调试用）

把本仓库根目录配成本地插件源，改代码后无需重新安装：

```bash
PLUGIN_LOCAL_REPO_PATHS=/path/to/VarietyPilot
PLUGIN_AUTO_RELOAD=true
```

本地源优先级高于远端市场，调试完记得移除，否则插件会一直读本地文件。

### 国内网络装不上怎么办

MoviePilot 装插件要走两个 GitHub 域名，任一不通就装不了：

| 用途 | 域名 | 能否走镜像 |
|---|---|---|
| 读插件索引 `package.v3.json` | `raw.githubusercontent.com` | 能，走 `GITHUB_PROXY` |
| 列目录、判断插件源码 | `api.github.com` | 不能，只能走 `PROXY_HOST` |

最省事的做法是配 HTTP 代理（两条链路一起解决）：

```bash
PROXY_HOST=http://192.168.x.x:7890
```

只配镜像的话，索引能读到，但列目录仍会失败：

```bash
GITHUB_PROXY=https://ghfast.top
```

> 索引读不到时，日志里会出现 `[GitHub] 所有策略均无法读取插件索引`；列目录失败会提示「连接仓库失败」或「超出速率限制」。
> 后者如果是 403，还可能是匿名 API 限额用尽，配一个 `GITHUB_TOKEN` 可提升到每小时 5000 次。

装不上又懒得折腾网络的话，直接用「方式二」手动拷目录，效果完全一致。

## 三、配置

| 配置项 | 说明 |
|---|---|
| 启用插件 | 总开关。关闭后不扫描，事件拦截也停止 |
| 预演模式 | **默认开启**。只匹配不下载，用于首次核对 |
| 发送通知 | 扫描与入库结果推送到 MP 通知渠道 |
| 自动同步 MP 订阅中的综艺 | 默认开启。从现有订阅里按 TMDB 类型挑出综艺，自动加入跟踪列表 |
| 同步范围 | 「仅综艺」按 TMDB 的真人秀/脱口秀类型判断；「全部电视剧」则不限 |
| 不跟踪的 TMDB ID | 订阅里有、但不想让插件处理的剧，多个用英文逗号分隔 |
| 跟踪的综艺 | 手动补充：每行一部 `剧名\|TMDB ID`，第三段可填年份或别名 |
| 扫描周期 | 可视化 Cron 选择器，默认 `*/30 * * * *` |
| 限定站点 | 多选下拉，直接读宿主站点库；不选表示全部站点 |
| 最小做种数 / 体积上下限 | 过滤低质量资源 |
| 偏好清晰度 | 1080p / 2160p / 720p，同集多版本时按此择优 |
| 入库后刷新媒体库 | 整理完成后主动触发极影视/Emby 刷新 |
| 允许重复下载已有集 | 默认关闭。开启后会重复提交已有特别集 |
| 特别季缓存(小时) | TMDB 特别季索引缓存时长，默认 12 小时 |

### 自动跟踪订阅里的综艺

开启「自动同步」后，插件会：

1. 读 MP 现有电视剧订阅，按 TMDB 媒体类型只取电视剧；
2. 用 TMDB 的类型判断是不是综艺（真人秀 `10764`、脱口秀 `10767`），结果缓存 30 天；
3. 同一部剧有多个季订阅时合并成一条，按剧去重；
4. 与手写列表合并，**手动配置优先**，不会重复。

同步时机有三处：插件启动 90 秒后补一次、每轮扫描开始前、以及调用 `/sync` 接口手动触发。
判断结果写进 `auto_shows.json`，重启后按缓存立即生效，不用等网络。

类型查不到的剧会跳过并在插件页「订阅同步」里列出原因，不会静默消失。
如果某部剧在 TMDB 上没标真人秀、但你想让插件处理，把它从订阅同步里排除，改用手写列表加进来即可。

### 剧列表写法（手动补充用）

```
现在就出发|231620|2023
我家那闺女|126490|我家那闺女2026,我家那闺女5
```

- 第一段：TMDB 上的中文剧名
- 第二段：TMDB ID（剧集页地址 `themoviedb.org/tv/` 后面的数字）
- 第三段：可选。纯数字当年份，否则当别名（逗号分隔），别名参与搜索

**英文名不用手填**。插件会自动从 TMDB 取该剧的中文名、原名和别名
（通常就是 `Natural High`、`Up All Friday Night` 这类站点在用的英文标题）一起搜索。
只有当站点用了 TMDB 上根本没有的译名时，才需要手动补在第三段。

## 四、首次使用：务必先预演

1. 打开「预演模式」，保持「自动同步 MP 订阅」开启，保存并启用。
2. 等 90 秒（启动后会补一次订阅同步），或在插件页调用 `/sync` 接口。
3. 打开插件页看「订阅同步」和「跟踪列表」，确认识别到的综艺对不对；不对的加进「不跟踪的 TMDB ID」。
4. 等一个扫描周期，或调用 `/scan` 接口。
5. 看「上次扫描结果」：每条应为 `[预演] S00E57 ← 《现在就出发.S03E08.第1期.加更.1080p》`。
6. 用 `/preview?tmdb_id=231620` 核对 TMDB 特别季的集号与集名是否对得上。
7. 确认无误后关闭预演模式。

## 五、和极影视 / Emby 的配合

极影视官方帮助中心的两条限制决定了本插件的写法：

| 官方说法 | 插件的应对 |
|---|---|
| 元数据依赖 TMDB，季集在 TMDB 不存在就难识别 | 只用 TMDB 真实存在的特别集号，不凭空编号 |
| 「特别篇/花絮这类内容通常较难自动识别」 | 把衍生内容统一归到 `Season 00`，走特别篇通道，而不是混在正片季里 |
| 文件名 `[]` 内内容会被忽略 | 季集号一律放在方括号外 |
| 季集号建议两位数字 | 季号固定 `S00`，集号至少两位（`S00E05`、`S00E128`） |
| 支持标准 NFO | 当前版本不生成 NFO；极影视按 TMDB 特别篇直接刮削 |

落盘路径形如：

```
现在就出发 (2023)/
├── Season 03/
│   └── 现在就出发 - S03E01 - ….mkv
└── Season 00/
    ├── 现在就出发 - S00E57 - 第3季 第1期加更.mkv
    └── 现在就出发 - S00E59 - 第3季 第1期还有加更.mkv
```

Emby 里显示为「特别篇」，极影视里同样归入该剧的特别季。

> 说明：极影视对 `Season 00` 的显示效果与固件版本有关。首次入库后建议去极影视确认一集；如果确实不显示，可先用 Emby 兼容模式挂载验证，再决定是否调整媒体库目录结构。

## 六、TMDB 还没登记的内容怎么处理

TMDB 的特别篇是人工维护的，新一期加更可能比站点发布晚几天。

插件遇到这种情况：

- **不猜集号、不硬塞**，避免在媒体库里生成没有元数据的脏条目；
- 记录到「等待 TMDB 补齐」列表，页面可查，含标题、期号、类型、已出现次数；
- 每轮扫描自动重试，TMDB 补齐后下一轮直接下载落位。

这一条对应页面上的独立卡片，也是排查「为什么这期没下」的第一现场。

## 七、匹配规则

PT 站点的资源名和节目信息是分开的，插件两个字段都读：

| 来源 | 内容 | 举例 |
|---|---|---|
| 种子名 `title` | 英文剧名、站点编号、压制参数 | `Natural High S04E08 Plus 2026 2160p TX WEB-DL H265 DDP2.0-ADWeb` |
| 站点副标题 `description` | 中文剧名、真实期号、衍生类型 | `现在就出发 第四季 加更 第04期还有加更：…` |

**站点编号 ≠ 真实期号**：上例站点写 `E08`，真实是第 4 期加更，两者必须分开记录。
插件用副标题里的「第X期」做匹配，用站点 `E08` 做整理阶段的回连依据。

**同一期会被拆成多集**：TMDB 里第 4 期的纯享就有 6 条（`第4期上纯享·不眨眼唱歌`、
`即兴MV`、`天黑吃香蕉`，`第4期下纯享·遥控器猜词`、`小画家`、`拍卖猜歌`）。
站点这边它们各占一个 `SxxExx`，副标题里的期号却完全一样。如果每条资源各取最高分，
它们会全部撞到同一集——这正是 v2.1.0 里「三条纯享全落 S00E159」的原因。

v2.1.1 起改为**落位分配**：一个集号只给一条资源。

1. 同一份内容的多清晰度版本、多站点版本先归为一组，整组落到同一集；
2. 组按站点发布顺序（`SxxExx` 升序）依次挑分最高、且尚未被占用的集号；
3. 集号用完了就进「等待」，绝不两条资源挤一集。

字号按以下维度打分，达到阈值才落位：

| 信号 | 说明 |
|---|---|
| 季 | `第4季` / `S04` / 年份映射（`2026` → 该剧 2026 年那一季） |
| 期号 | 副标题里的 `第X期` 优先于种子名的 `SxxExx`；只有站点编号时不参与比对 |
| 类型 | 加更族 / 彩蛋 / 纯享 / 先导 / 特辑 / 直播 / 直拍 / 其他衍生 |
| 修饰词 | `还有加更`、`再次加更`、`超前加更`——区分同季同期同类型的多条 |
| 分P | `上/下`、`Part1/2`，对应 TMDB 里拆成两条的加更 |
| 片段名 | 副标题冒号后的内容与 TMDB 集名 `·` 后的内容比对，同名即同一段 |
| 日期 | 前几项不足时用播出日期兜底，2 天内加分、4 天内少量加分 |

打分达到阈值才落位，达不到就进「等待补齐」。宁可不下，也不错位。

### 两条安全边界

1. **正片不进入插件链路**：副标题标了「正片」、或通篇没有衍生标记的资源，既不下载也不改写。
2. **整理阶段只认衍生标记**：同剧正片与加更可能同季同集号（只差一个 `Plus`），
   所以改写前必须确认文件名带衍生标记，或与种子名完全一致。判不出来就不改，
   文件落回正片季——肉眼可见、可以手工处理，而不是把正片塞进 Season 00。

## 八、已知限制

1. **必须 TMDB 有特别季**。没有特别季的综艺，插件会跳过并在扫描结果里提示。这类剧只能等 TMDB 补建，或在 TMDB 上手动补录特别集。
2. **搜索词依赖 TMDB 别名**。插件会自动取 TMDB 的中文名、原名和别名（通常是英文名，如 `Natural High`）参与搜索；如果站点用的是 TMDB 上没有的译名，请手动把它加进剧列表第三段。
3. **不处理整季包**。整季合集不拆分，直接跳过。
4. **极影视对 S00 的显示需实测**。插件保证文件结构和 TMDB 一致，但播放器行为取决于固件版本。
5. **不做洗版**。同一特别集已有任务时默认不重复下载，除非手动开启「允许重复下载已有集」。
6. **整理阶段靠文件名回连**。如果站点把文件改成不带任何标记的通用名（如 `EP08.mkv`），插件无法确认它是不是衍生内容，会放弃改写。

## 九、测试

仓库内 `tests/` 为回归测试，数据取自 TMDB 真实集名与 PT 站点真实资源名：

```bash
python tests/test_titles.py        # 32 个标题解析用例
python tests/test_sxxindex.py      # 16 个特别季匹配用例
python tests/test_renaming.py      # 5 个路径改写用例
python tests/test_pipeline.py      # 端到端扫描与整理拦截
python tests/test_real_titles.py   # 真实 PT 资源名：解析 / 匹配 / 正片拦截 / 免费优先
python tests/test_subscribes.py    # 订阅发现：类型判定、去重合并、排除名单、缓存
python tests/test_assignment.py    # 落位分配：同一期多条纯享分落不同集，不重复占用
```

`test_assignment.py` 用的是 TMDB《现在就出发》第四季的真实集名（138–167 集），
复现了「三条 Pure 全落 S00E159」的现场：现在它们分别落到 159/160/161，
带片段名时精确命中 164/165。

`test_pipeline.py` 覆盖了：正片不被误下、加更与还有加更分别命中、同期多版本择优、整季包跳过、重复扫描不重复下载、无关文件不被改写。

`test_real_titles.py` 用的是站点上真实存在的资源名，例如：

```
Natural High S04E08 Plus 2026 2160p TX WEB-DL H265 DDP2.0-ADWeb
  副标题：现在就出发 第四季 加更 第04期还有加更
  → S00 的《第4季 第4期还有加更》，而不是站点编号 E08
```

## 十、文件说明

| 文件 | 职责 |
|---|---|
| `__init__.py` | 插件主类：配置、定时、事件拦截、API、页面 |
| `titles.py` | 标题解析：类型词表、期号、季号、修饰词、分P、日期 |
| `sxxindex.py` | TMDB 特别季索引与打分匹配 |
| `renaming.py` | 整理路径改写（渲染前改字典、渲染后改字符串） |
| `pipeline.py` | 扫描编排：搜索、分类、择优、生成任务 |
| `store.py` | 任务与未匹配记录的持久化 |
| `subscribes.py` | 订阅发现：读 MP 订阅、按 TMDB 类型筛综艺、类型缓存 |

### 仓库结构

```
VarietyPilot/
├── package.v3.json           插件库索引（插件市场读这个文件）
├── icons/varietypilot.png    插件图标
├── plugins.v3/
│   └── varietypilot/         插件本体，目录名必须是插件 ID 的小写
├── tests/                    回归测试
└── README.md
```

新增插件时，在 `package.v3.json` 里加一条以插件 ID 为键的记录，再把代码放到 `plugins.v3/<id 小写>/`。签名约定：目录名小写、`__init__.py` 里的类名与 ID 完全一致。

### 版本发布约定

改代码后按这三步走，插件市场才会提示更新：

1. 改 `plugins.v3/varietypilot/__init__.py` 里的 `plugin_version`
2. 改 `package.v3.json` 里的 `version`，并在 `history` 里加一条同版本号的说明
3. `git push`（`main` 分支）

插件市场以 `package.v3.json` 的 `version` 判断是否有新版，两处不一致会导致市场显示旧版本。
